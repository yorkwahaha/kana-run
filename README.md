# 五十音疾走 · KANA RUN

以**適性化間隔重複（SRS）**為核心的五十音記憶跑酷。Godot 4.7，全程程式化生成——
專案內沒有任何 3D 模型、貼圖或音檔，clone 下來就能跑，也沒有第三方授權負擔。

---

## 為什麼它不只是「原版加畫面」

原版 HTML 的核心問題是：**題目只有「羅馬字 → 假名」，測的是背五十音圖，不是閱讀。**
這個版本把玩法往真正的閱讀訓練推：

| 機制 | 說明 |
|---|---|
| **三種題型** | `ROMAJI` 羅馬字選假名 / `WORD_BLANK` 挖空詞彙（`○つ` + 鞋・鞋子）/ `KANA_READ` 看假名選羅馬字（反向）/ `BOSS` 混淆決戰 |
| **難度曲線** | 依進度解鎖題型；前期暖身，中期詞彙，後期反向 + 混淆決戰 |
| **干擾項來自混淆群** | 目標是 `か` 時干擾優先取 `が/さ/は/き`，而不是三個亂數。**並自動排除同音假名**（`を` 與 `お` 都唸 o，絕不能當干擾） |
| **閃避** | 按 ↓ 可以跳過一題：扣體力、不扣連段、題目保留稍後再考。失敗變成可重試的迴圈 |
| **時間壓力 + 連段** | 撞破瞬間依反應時間評 PERFECT / GREAT / GOOD，連段累積倍率至 ×3（前 5 題會顯示一次說明，因為不知道有分級的話，PERFECT 這兩個字對新手沒有意義） |
| **遺物（Roguelite）** | 每 10 題三選一，共 10 種。同一套題庫能跑出十幾種節奏 |
| **SRS 排題** | 新音依五十音圖順序；舊音依「弱度 × 遺忘天數 × 反應遲鈍」加權複習。第一局像課程，第三局像教練 |
| **學習診斷** | 結算畫面列出最需要複習的假名（掌握度色條）與反應最慢的假名；儀表板有 208 音掌握度地圖 |
| **詞彙寶石** | 持有「採集」遺物時路上浮現寶石，收集進單詞本 |

### 幾個關鍵實作決定

- **世界往鏡頭移動**，跑者固定在 z=0。長跑不會有浮點精度問題，物件只需回收重生。
- **倒角盒**（`SceneKit.chamfer_box`，44 個三角面）而不是 `BoxMesh`：倒角稜線挑出的高光
  是「有 3D 資產」與「只有一個盒子」最明顯的差別。
- **字型分兩套**：UI 用 Noto Sans TC（日式字型沒有「讀／錄／產／擊」等繁體字），
  碑面大字用 Zen Kaku Gothic New Black。只有 kana 與拉丁字的部分進 display 字型（45 KB）。
- **`hint_screen_texture` 後製**：徑向模糊取螢幕紋理的粗略 mip，配合速度、色散、暗角與顆粒。
- **打擊停滯**：答對瞬間 `Engine.time_scale` 掉到 0.06 維持 0.09 秒，是打擊感的來源。
- **暫停／遺物畫面 pause 整棵樹，但 `Main` 是 `PROCESS_MODE_ALWAYS`**：流程轉換需要它醒著，
  而 3D 節點個別設為 `PAUSABLE`，暫停時場景才真的凍結。

## 換 BGM 與音效（不用改任何程式碼）

把音檔丟進這兩個資料夾，重新啟動遊戲就會生效：

```
I:\Projects\Kana Run\audio\music\     ← 背景音樂（mp3 / ogg / wav / m44 都可）
I:\Projects\Kana Run\audio\sfx\       ← 覆蓋單一音效，檔名必須完全一致
```

**背景音樂**：`audio/music/` 裡的每個檔案都會被視為一首曲子，啟動時隨機挑一首播放，
並且會出現在**設定 → 背景音樂**頁面。支援多首。資料夾空的話就使用內建的程序化配樂。

設定頁可以選兩種播放方式：

| 模式 | 行為 |
| --- | --- |
| 單曲循環（預設） | 目前這首循環播放。Godot 匯入 mp3 預設不循環，程式會手動開 `loop` |
| 全部輪播 | 關閉 loop，一首播完自動接下一首 |

旁邊還有「重播」（立刻重播目前這首）與「下一首」兩個按鈕。

**遊戲執行中丟 mp3 進去也會自動接上**（每 2 秒重掃一次資料夾），
但前提是該檔案已經被 Godot 匯入（旁邊要有 `.import`）。
用 `play.bat` 啟動會自動先做匯入，所以最省事的流程是：**丟檔案 → 關掉遊戲 → 雙擊 play.bat**。

啟動時主控台會印出偵測結果，例如
`[sfx] 外部 BGM：kanade` 或 `[sfx] 外部音效覆蓋：shatter`。

> ⚠️ 匯出網頁版時音檔會整個塞進 `.pck`。**7 MB 的 mp3 會讓下載變慢**，
> 建議壓成 128 kbps 單聲道，或用短一點的 loop。


**音效**：把檔名取成下面其中之一，就會蓋掉對應的內建音效：

| 檔名 | 觸發時機 |
|---|---|
| `shift` | 換線 |
| `shatter` | 撞碎石碑（答對） |
| `miss` | 答錯 |
| `tap` | UI 點擊 |
| `back` | UI 返回 |
| `tick` | 倒數滴答 |

沒有對應檔案的音效會繼續用內建合成音色，所以你可以只換其中一兩個。

啟動時主控台會印出偵測結果，例如
`[sfx] found 2 external BGM track(s): calm, night` 與 `[sfx] external SFX overrides: shatter`。

### 內建音色的問題與修法

原本的合成音色「聽久了刺耳」，原因是鋸齒波與高次諧波直接送進喇叭。
現在 `_render()` 會做兩件事：

1. **單極低通濾波** —— 每個音色各自指定截止頻率（bass 1.8kHz、bell 3.4kHz、pad 2.4kHz…），
   高頻被壓掉之後，木質感反而出來了。
2. **`tanh` 軟飽和** —— 取代硬截斷，峰值會圓潤，不會有數位爆音。

另外把 `bell` 的 5.4 倍頻（最刺耳的那個）拿掉，答錯音效從不協和鋸齒改成柔和的下行木質音，
配樂預設音量也從 0.5 降到 0.38。**如果你還是覺得內建配樂不耐聽，直接一 mp3 進 `audio/music/` 蓋掉它是最快的解法。**

## 語音包（聽力題）

```
I:\Projects\Kana Run\audio\kana\     ← 依羅馬字命名：a.mp3 / ka.mp3 / kya.mp3 / shi.mp3 …
```

檔名必須是該假名的**羅馬字讀音**。放進去之後「聽音辨字」題型會自動解鎖（約 14% 的題目），
沒有的音會自動退回羅馬字題，不會出錯。

**單字題也會唸出聲。** 單字題顯示的是挖空的單詞（靴　○つ）與釋義，
不會念假名的人看到挖空根本無從選起 —— 所以會依序播放整個單詞的讀音
（一個假名一段，**每段播完才接下一段**）。只播「答案那個音」等於把答案唸給玩家聽，
所以不那麼做。

> 逐音必須「等前一段 `finished` 再播下一段」。早期版本用固定 0.1 秒計時器換 stream，
> 同一個 `AudioStreamPlayer` 換音檔會截斷前一段，實際聽起來只剩最後一個音。

### 整詞錄音（選用，但強烈建議）

逐音接接聽起來像三個獨立的音，不是一個詞。要聽出「靴　○つ」該填哪個音，
需要的是整個詞的節奏。把整詞錄音丟進 `audio/words/` 就會自動優先使用：

```
I:\Projects\Kana Run\audio\words\     ← 檔名 = 平假名讀音：りゆう.ogg / びーる.mp3 …
```

副檔名 `ogg → mp3 → wav → m4a` 依序查找，找到第一個就停。
**讀音必須寫成平假名**，寫成片假名會查不到。細節見 `audio/words/README.md`。

逐音 fallback 永遠保留，兩種可以混著用；只要放了整詞錄音，那一題就「只有那一段」，
不會變成整詞後面又接一次逐音。

`tools/word_audio_test.gd` 會驗證「凡是單字題，就一定有音檔」，目前 83/83 = 100%。
它同時守住三個容易壞掉的點：
- 拗音必須切成兩字（`きゃく` → `きゃ` + `く`），逐字切會讓 `ゃ` 查不到音檔
- 詞庫的讀音欄必須是平假名。`パン/ビール/プール/ページ/ポスト` 原本存成片假名，
  導致 `reading.find(kana)` 找不到那個假名，單字題會整個靜默退回羅馬字題。
- 整詞與逐音不可混用，否則同一個詞會被唸兩次

你現有的 `I:\Projects\50on puzzle\public\kana` **可以直接用**：
102 個 mp3 剛好覆蓋全部 104 音（`じ/ぢ` 共用 `ji.mp3`、`ず/づ` 共用 `zu.mp3`），
已經複製到專案裡了。

## 執行

專案根目錄有四個可以直接**雙擊**的批次檔（Windows）：

| 檔案 | 用途 |
|---|---|
| **`play.bat`** | 啟動遊戲（正式版）。會先自動匯入資源再開跑 |
| `editor.bat` | 用 Godot 編輯器開啟專案 |
| `selftest.bat` | 跑完整檢查：題目不變量 + 輸入管線 + 接地檢查 + 單字題音檔 + 兩種完賽測試 |
| `export-web.bat` | 匯出網頁版到 `build/web/` |

`play.bat` 會依序尋找 Godot：`GODOT_BIN` 環境變數 → `I:\Projects\Godot_v4.7.2\` →
掃描 `I:\Projects\Godot*` → `PATH`。都找不到時會提示你設定 `GODOT_BIN`。

> **為什麼 `.bat` 會先跑一次 `--import`？**
> Godot 執行時 `load()` 一個 mp3，需要該檔案已經被匯入（旁邊有 `.import`）。
> 你把 mp3 丟進 `audio/music/` 之後，若沒有人在旁邊跑著編輯器，那個匯入就不會發生，
> 遊戲就會讀不到。`play.bat` 每次啟動都會先補做匯入，所以你只要丟檔案 +
> 關掉重開就好。（已經在遊戲執行中時丟檔案，遊戲會在 2 秒內自動重掃並接上。）

## 操作

**鍵盤**

| 按鍵 | 動作 |
|---|---|
| `A` `D` / `←` `→` | 左右換線 |
| `1` `2` `3` | 直接跳到左／中／右跑道 |
| `↓` / `S` / `X` | **棄題／蹲下**：答題中按 = 棄掉那一題（稍後再考，扣 9 體力）；橫桿前按 = 蹲身通過 |
| `Esc` / `P` | 暫停選單 |
| `R` | **立即重開**：結算、倒地、暫停都直接回第一題，不進選單（倒地後 0.5 秒內不生效） |

**觸控（手機／平板）**

| 手勢 | 動作 |
|---|---|
| 螢幕左右滑 | 換線 |
| 螢幕下滑 | 閃避／蹲下 |
| 點左／右三分之一 | 換線（中間不反應，避免誤觸） |
| 畫面左下「左」「右」「蹲」三顆按鈕 | 換線與蹲下（只在偵測到觸控螢幕時顯示） |

橫向手勢與點擊可以並用，兩邊都送到同一組語意動作。下滑要 42px 以上才成立；
一幀只會做一個動作，所以下滑不會同時觸發換線。

### 進度條上的小跑步者

左上角的進度條上有一個會跑的小人，沿著條往終點旗移動 —— 原本只是一條填色長條，
玩家看不出「還有多久」。小人與未完成的部分都畫得出來，剩餘距離就變成一眼可讀的資訊。

### 關卡

| 關卡 | 內容 |
|---|---|
| 清音篇 | 46 音，一切的起點 |
| 濁音・半濁音篇 | 25 音，點與圈的世界 |
| 拗音篇 | 33 音，組合的韻律 |
| 片假名篇 | 104 音，同一套音、另一套字形 |
| 大滿貫 | 208 音，平假名＋片假名 |

片假名單元不是另外手寫 104 筆，而是**由前三個平假名單元自動轉換**而來
（`KanaDB._ensure()`）。手寫的話兩邊遲早會對不起來，而且清音／濁音／拗音
增減時要同步改兩個地方。詞庫與混淆群也會自動映射到片假名版本，
所以挖空題與混淆決戰在片假名關卡一樣能出。

### 路面的捲動方向

`road.gdshader` 的 `scroll` 取**負號**。PlaneMesh 的 `v=0` 在遠端、`v=1` 在近端，
而 `f(p + c*t)` 會讓特徵往 `p` 減小的方向移動 —— 原本的正號會讓路面紋理往**遠處**流，
與幾何虛線往近處移動正好相反，看起來就像在追著馬路跑。

### 一局的結構

一局 46 題切成四區，每區 12 題。換區會跳章節卡、換天色與天氣，並改變玩法：

| 區 | 場所 | 特色 |
|---|---|---|
| 第一區 | 草木 | 飄落花瓣，基準速度，先熟悉節奏 |
| 第二區 | 雨 | 霧變濃、**真的在下雨**（細長水痕，420 條） |
| 第三區 | 神社 | 連段倍率成長加倍 |
| 第四區 | 嵐 | 速度推到接近上限，橫向風雨，撐到終點 |

換區卡放在**題卡右側的空白欄**，不放畫面中央 ——
中央那帶正是遠方石碑所在，提示一跳出來就會蓋住下一題的碑面假名。

**每局開頭都會重設天氣。** 否則會出現「一旦下雨就永遠在下雨」：
開局時 `_zone` 已經是 0，`_check_zone()` 會提早 return，
於是分區設定從沒被套用過，上一局的天氣就這樣留到下一局。

第二～四區之間會插入一個 3.2 秒的**衝刺關**：速度 ×1.22、得分 ×2，
左上角會持續顯示「衝刺」直到結束。

**橫桿障礙**：每答完 5 題會插入一波只有橫桿、沒有題目的障礙波。橫桿**只擋其中兩條跑道**，
另外一條是綠色矮欄，站著直接通過：

| 情況 | 結果 |
|---|---|
| 在綠色空道 | 免費通過，回 5 點體力 |
| 在紅白條上按 `↓` 蹲下 | 閃過，但扣 9 點體力、不計分 |
| 在紅白條上沒蹲 | 撞飛，扣 18 點體力、斷連段 |

**閃避不是免費的，而且不該無腦按。** 最初的版本讓橫桿橫跨整條路，
三條道都必須蹲 —— 那就只是按一下按鈕，沒有判斷可言。留一條空道之後，
最佳解變成「先換到綠色空道」，蹲下只是被逼到紅白條時的退路。

障礙波不消耗 SRS 題目，所以 46 題的學習節奏不會被打壞。
（也刻意不在障礙波排題：「躲得過橫桿」和「站在答對的跑道」兩個目標會互相衝突，
實測過那樣每局會多錯 5 題。）

**體力用盡**不會直接跳結算畫面，會依原因分成兩種結局：
| 情況 | 結局 |
|---|---|
| 慢慢耗盡（沒撞到東西） | 往前撲一下，然後**跪坐在路中間**低頭喘氣，維持不動 |
| 撞到東西時體力正好歸零 | 被**撞飛出去，趴在地上**，只剩微弱的呼吸起伏 |

兩種都會讓跑道停下來 —— 減速集中在前 0.45 秒，之後完全不推進，
並且鏡頭推近到角色身上（趴姿的投影很小，不推近看不出姿勢）。整段 1.9 秒後才進結算。

**被撞飛的三個關鍵點**，少一個就會退回「在原地倒下」：

1. **鏡頭要追著飛。** 鏡頭停在原位時，角色往前 5.6 公尺會讓距離從 10 變成 15.6 公尺，
   投影縮小三分之一 —— 畫面上看起來是「跑掉了」而不是「被撞飛」。
   `camera_director.follow_flight()` 跟著角色的 z／y 位移走（插值係數 5.0／7.0），
   落地後自然插回原鏡位。
2. **落地那一幀不能翻身。** 空中總共轉 2.5 圈（`-t * PI * 2.5`），末了剛好是 −90°，
   和趴地姿勢完全接得上。若只轉 1 圈，落地瞬間會整個人瞬間翻面 180°。
3. **鏡頭推近要等落地。** 撞飛時先 `set_dolly(false)`，跑完 0.62 秒的飛行才推近 ——
   飛行途中就推近，「往前飛出去」會變回「在鏡頭前倒下」。

飛行參數集中在 `runner._process_fling()`：0.62 秒、前進 5.6 公尺、拋高 1.3 公尺。
`--flung` 必須搭配 `--perfect`（或 `--autoplay`）才會直接開局，
否則只會停在標題畫面。

### 極限（OVERDRIVE）

**連段 30 就進極限，斷了立刻掉出來。** 極限下石碑以 0.176 秒週期快速明滅、
得分 ×3、體力消耗 ×1.9、速度 ×1.18、配樂強度拉到 0.9。

這個狀態存在的理由不是「獎勵連段」，而是**讓一局有峰值**。
原本 46 題是一路加速的斜坡，跑到最後和跑到第 20 題的差別只是數字比較大，
沒有「進入了某個階段」的轉折，跑完也就跑完了。

三個設計決定值得記下來：

- **必須由玩家自己賺來。** 門檻是連段，不是隨機發放。
  這樣失敗時的刺痛感是「我貪了倍率」，不是「題目突然變難」。
- **要有代價。** 體力 ×1.9 讓極限是一個交換而不是白送分數。
  沒有代價的話玩家會無腦待著，不會有「再撐三題」的念頭 ——
  而那個念頭就是「想再玩一次」的來源。
- **閃爍不是淡出。** 淡出到看不見等於把題目拿走，玩家會覺得被剝奪作答機會，
  那是在懲罰他。明滅是「還在這裡，但你要更快」—— 機會還在，只是要靠記憶補上。
  滅的最低值停在 0.42 而不是 0，因為極限的週期遠小於一題的推進時間，
  全黑那一格在單張截圖裡會讓整顆消失，但玩家實際看不到那麼久。

實測：`--perfect` 得分約 105k，開啟極限後約 177k（連段 46 → 76，
因為 `mugen` 之外的連段倍率在極限下不再被 3.0 天花板壓住）。

### R 鍵立即重開

結算、倒地被撞飛、暫停畫面都按 R 直接回第一題，不進選單。

「想要再來一把」和「正在玩」之間的距離，就是黏著性的一半。
原本隔著選單是兩次點擊，對已經有衝動的玩家來說足以讓他冷掉；
現在按下去那一刻就已經在跑。

唯一例外：倒地後 0.5 秒內 R 不生效 ——
那 1.9 秒的收尾是失敗的重量，拿掉它失敗就沒有後果感。

**地板的靜止是獨立控制**：`set_speed01(0)` 並不會讓路面停下來，因為路面 shader 的捲動速度是
`lerp(3, 16, speed01)`，速度歸零時它仍然是 3，貼圖會繼續滾，看起來就像輸送帶。
所以另有 `track.set_frozen()` 把捲動、風線、花瓣一起關掉，用在**倒地、三選一、暫停**三個地方。

**接地修正**：摔倒姿勢是手動拼出來的旋轉角度，沒有任何機制保證身體貼在地面上 ——
實測趴地姿勢會沉到路面下 0.83 公尺。現在每幀量一次所有可見網格的世界座標最低點，
再把整個 rig 補到剛好貼地。`tools/prone_test.gd` 會驗證這件事。

### 字型

```bash
python tools/subset_fonts.py          # 需要 fonttools
python tools/subset_fonts.py --check  # 只檢查缺字，不寫檔
```

工具會掃描所有 `.gd` / `.gdshader` 字串常值（先去掉註解），檢查每個字是否三個字型都畫得出來，
並列出原始檔位置。**改動任何遊戲內文字後請重跑**，否則新字會變成空白方塊。

### 除錯用的命令列參數

全部集中在 `main.gd` 的 `_parse_test_args()`：

| 參數 | 用途 |
|---|---|
| `--selftest` | 產生近 2.5 萬題驗證題目不變量 |

| `--miss` / `--holdmiss` | 每題都撞錯；`--holdmiss` 會停在錯題卡上 |
| `--watch` | 持續檢查三根石碑是否都在，缺一根就印出上下文 |
| `--turbo=N` | 時間加速 N 倍（跑完整局用） |
| `--shot[=N] out.png` | 第 N 幀截圖 |
| `--page=brief\|levels\|dashboard\|settings\|results` | 直接開某個畫面 |
| `--qtype=0..4` | 強制指定題型（0 羅馬字／1 挖空詞／2 反向／3 聽力／4 混淆決戰） |
| `--holdrelic` / `--holdend` | 停在遺物／結算畫面 |
| `--relics` | 預先塞 4 件遺物，用來檢查底欄的遺物即時數值排版 |
| `--barrier` | 第一波就是橫桿障礙，用來截圖檢查外觀與閃避判定 |

| `--collapse` | 開局立刻體力用盡，檢查跪倒動畫 |
| `--flung` | 開局立刻「撞到沒體力」，檢查被撞飛趴地的動畫（需搭配 `--perfect` 才會直接開局） |

## 匯出

```bash
export-web.bat              # Web 版 → build/web/
python make_certs.py        # 自簽憑證（區網 https 測試用，只需一次）
python serve_web.py         # https 伺服器，預設 8443
```

第一次使用必須先在編輯器安裝 **4.7.2-stable 的 export templates**
（Project → Tools → Manage Export Templates，約 1.2GB）。

### 在平板／手機上試玩

**必須走 https。** 這不是偏好問題，是 Godot 4.7 的硬性要求（見下方坑 2）。

```bash
python make_certs.py    # 產生自簽憑證（只需一次）
python serve_web.py      # 預設 8443，會列出平板可用的網址
```

第一次在手機上連會跳「憑證無效」警告，這是自簽憑證的正常現象。
信任憑證後就永久有效：

| 裝置 | 做法 |
|---|---|
| iOS | 設定 → 一般 → VPN 與裝置管理 → 匯入 `build/certs/server.cer` → 安裝 |
| Android | 設定 → 安全性 → 加密與憑證 → 安裝憑證 → CA 憑證 → 選 `server.crt` |

已開 PWA，信任憑證後選「加入主畫面」會是全螢幕的樣子，首次載入後離線也能開。

### 兩個會浪費時間的坑

**1. `vram_texture_compression/for_mobile` 必須關閉。**
Web 平臺不支援 S3TC/ETC 紋理壓縮，開著會讓匯出直接失敗。

關鍵是 Godot 4.7 印的錯誤訊息是**空的**：

```
ERROR: Cannot export project with preset "Web" due to configuration errors:
ERROR: Project export for preset "Web" failed.
```

後面什麼都沒有，看起來像 template 沒裝或 preset 壞掉，
實際上是上面那個選項 —— 只能逐一停用選項二分找。

**2. Web 匯出一律需要 https（或 localhost）。**

瀏覽器只把 `https://` 和 `http://localhost` 視為 secure context。
區網 IP（`http://192.168.50.107`）走明文，**永遠不算**，
Godot 會在啟動時擋下來：

```
The following features required to run Godot projects on the Web are missing:
Secure Context - Check web server configuration (use HTTPS)
```

兩個容易誤判的地方：

- **伺服器端無法解決。** `window.isSecureContext` 由瀏覽器依協定決定，
  送再多 COOP/COEP 標頭也沒用。
- **關掉 `thread_support` 不足以跳過。** 原本以為是執行緒的問題，
  但讀 `index.js` 會看到 Secure Context 檢查寫死在 `if (supportsThreads)` **之外**，
  連單執行緒版本一樣要求。`export_presets.cfg` 目前維持 `thread_support=false`
  只是順帶減少依賴，不是解法。

唯一的路就是 `serve_web.py` 提供 https（或部署到有憑證的主機）。
`export_presets.cfg`、`serve_web.py` 都有註解記錄原因。

### 效能

- 行動端低配機請在設定把畫質調成「流暢」：會關閉 SSAO 並降低陰影品質。
- SSAO 只在 Forward+ 且畫質「精細」時啟用，Web 與多數 Android 裝置不會開。
- 粒子一律用 `CPUParticles3D`（GPU 粒子在 Web 上支援不完整）。
- 螢幕空間效果（徑向模糊等）走單次全螢幕 pass，不做多層疊加。
